# רשת משקפיים — React / Node.js / SQLite

גרסה 2.0. מימוש React של כיוון העיצוב 01 שנבחר. דף הבית שומר על המבנה שבתמונה: לוגו ותפריט, רקע משקפיים רציף, כותרת מימין, פס תיאום צף, שלוש כרטיסיות שירות ושורת שלושת הסניפים.

## דרישות
Node.js 24 ומעלה, npm. לחלופין Docker עם Docker Compose.

## הפעלה מקומית

    npm ci
    cp .env.example .env

הגדירו בקובץ .env סיסמת ניהול חזקה באורך 16 תווים לפחות תחת ADMIN_PASSWORD. אל תפרסמו קובץ זה.

    npm run dev

האתר ב-http://localhost:5173 וה-API מאחוריו. מסך הניהול ב-http://localhost:5173/#/admin.

## הרצת production

    npm ci
    npm run build
    npm start

גלשו ל-http://localhost:3000. לפני חשיפה לציבור, הפעילו HTTPS באמצעות reverse proxy והגדירו COOKIE_SECURE=true. מאחורי proxy שמחליף את Host, הגדירו PUBLIC_ORIGIN לכתובת HTTPS המדויקת של האתר. יש לאפשר גישה רק דרך ה-proxy ולהוסיף הגבלת קצב גם בשכבתו; מגבלת השרת מבוססת על כתובת החיבור הישיר.

## Docker
לאחר הגדרת ADMIN_PASSWORD ב-.env:

    docker compose up --build -d

האתר ב-http://localhost:8080 והניהול ב-http://localhost:8080/#/admin. הנתונים נשמרים ב-volume בשם bookings גם בהפעלה מחדש. אל תמחקו את ה-volume אם נדרש לשמור את הנתונים. לפני חשיפה ציבורית יש HTTPS, גיבוי ובדיקת הגדרות אבטחה.

## מבנה הפרויקט
- src/App.jsx — האפליקציה, ניווט, חיפוש וחלונות תוכן.
- src/components/ — Header, Modal, Booking ו-BranchCards.
- src/pages/ — Home, Collection ו-Admin.
- src/data.js — מלל, שירותים ופרטי סניפים.
- src/styles.css — עיצוב RTL והתאמה למסכים שונים.
- public/assets/ — הלוגו ותמונות מקומיות.
- server/index.mjs — שרת API ושרת קבצים, Node.js ו-SQLite.
- tests/api.test.mjs — אימות בקשות, הרשאות ומניעת אישור תורים חופפים.
- Dockerfile, compose.yaml — אריזת השרת והלקוח יחד.

קובץ index.html הקטן בשורש הוא קובץ הכניסה הנדרש של Vite; ממשק האתר עצמו ממומש בקומפוננטות React. אין לפתוח אותו ישירות בסייר הקבצים. יש להתקין ולהפעיל לפי ההוראות למעלה. כל התמונות והגופנים נארזים מקומית; אין טעינת CDN בזמן הגלישה.

## תורים וניהול
הלקוח בוחר סניף, שירות, מועד מועדף ופרטי קשר, מאשר שימוש בפרטים ושולח בקשה. השרת מאמת ושומר ב-SQLite ומחזיר מספר פנייה. הסטטוס הראשוני ממתין לאישור. זהו תהליך בקשות, לא הצגת יומן זמינות מחובר.

מנהל נכנס ל-/#/admin עם הסיסמה שהוגדרה בשרת, רואה בקשות, מסנן לפי סניף ומאשר או מבטל. המערכת מונעת אישור של תורים החופפים בטווח 30 דקות באותו סניף (משאב אחד לכל סניף). אין לוחות משמרות או שעות פעילות מוגדרות. הצוות חייב לבדוק זמינות ושעות פעילות לפני אישור וליצור קשר עם הלקוח. אישור במערכת אינו שולח הודעת SMS, WhatsApp או דוא"ל. לא מחובר ספק הודעות או יומן חיצוני.

בשרת נכללים אימות סיסמה, עוגיית ניהול HttpOnly/SameSite, הגבלת ניסיונות וולידציה בצד שרת. בשלב זה יש חשבון ניהול משותף יחיד לכל הסניפים. לפני עבודה רב-משתמשית יש להוסיף חשבונות, הרשאות פרטניות ויומן פעולות לפי דרישות הרשת. לצורך מחיקת נתוני לקוח יש לפנות למפעיל ולבצע מחיקה מבוקרת מהמסד; אין במסך זה פעולת מחיקה לצמיתות.

## הקישור המתארח ב-ChatGPT
הפרסום המתארח הנוכחי הוא תצוגת React סטטית. הוא אינו מפעיל את שרת Node.js או את SQLite. בהיעדר API, הממשק מזהה זאת ומציע לתאם בטלפון, ללא איסוף פרטי קשר או הצגת בקשה כאילו נשמרה. מערכת הבקשות המלאה פועלת בהרצת Node.js או Docker המתוארת לעיל.

## תוכן השיחה
פירוט השירותים כולל מעבדה בחנות ומלאי עדשות, הכנה במקום בכפוף למרשם ולזמינות, מבחר מסגרות מפעוטות ועד מבוגרים ומולטיפוקל, בדיקות ממוחשבות בפיקוח אופטומטריסט, מיפוי קרנית, מדידת לחץ תוך-עיני, צילום רשתית בתיאום (המצלמה מועברת בין הסניפים), בדיקות מיקוד ושירות מותאם לקהילה.

החלק בתמלול על עדשות לילדים פורש כאפשרות לייעוץ בנושא ניהול קוצר ראייה; יש לאשר מול איש המקצוע את המינוח והטיפול המוצע. המספרים 80%, 13% והטענה שרק ארבע מצלמות כאלה בארץ לא פורסמו. נדרשים מקור, הגדרת המדד, דגם המכשיר ואישור מקצועי לפני שימוש בפרסום. לא הובטחה עצירת מספר או זמן אספקה אחיד, ולא נכתב שהמכשיר מחליף אופטומטריסט.

תמונות המוצר, המכשור והחנויות נוצרו להמחשה ואינן תיעוד של סניפי הרשת או ציוד מדגם מסוים. תמונות הסניפים מסומנות בהתאם; החליפו בתמונות מקוריות כשיהיו זמינות. הקולקציה היא איורי סגנונות, לא מלאי מסחרי. פרטי הקופות, שעות הפעילות, מדיניות הפרטיות, שמירת המידע ונגישות טעונים השלמה ואישור הרשת לפני השקה לציבור.

## בדיקות

    npm test
    npm run build

נבדקו API, אי-חשיפת בקשות ללא כניסה, ולידציה, כניסה ויציאה, מניעת אישורים חופפים ושמירת בקשה דרך ממשק React בתצוגה המקומית. סביבת התצוגה נבדקה ברוחב מחשב ובמסגרת נייד 390px. Dockerfile נכלל; אם Docker אינו מותקן במחשב הבדיקה, לא ניתן לאמת שם בניית image בפועל.

גיבוי: יש לגבות את מסד SQLite באופן עקבי באמצעות SQLite backup או בזמן עצירת השירות. ה-volume אינו תחליף לגיבוי חיצוני.
